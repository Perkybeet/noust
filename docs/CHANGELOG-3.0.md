# Noust 3.0 changelog

Changes since WASM 2.3.0. Upgrade notes are in [UPGRADING-3.0.md](UPGRADING-3.0.md).

## WASM is now Noust

"WASM" means WebAssembly to every search engine, package index and command line, which kept
the project from being found. 3.0 renames it. In Orkney and Shetland, a *noust* is the hollow
on the shore where a boat is drawn up and sheltered between voyages: your server is the
noust, your applications the boats.

- **The command is `noust`.** `wasm` runs the same program for the whole 3.x series, so no
  operator script or cron line breaks on the upgrade; typed at a terminal, it says once that
  the product is now Noust. `noust --version` prints "Noust X (formerly WASM)".
- **Packages**: `noust` on PyPI and in the `home:Perkybeet` repository for apt, dnf and
  zypper. `wasm` (Debian, Ubuntu) and `wasm-cli` (Fedora, openSUSE, PyPI) are empty
  transitional packages that depend on `noust`, so the usual upgrade command brings it in.
  The default configuration ships as a reference at `/usr/share/noust/config.example.yaml`.
  See [RENAME.md](RENAME.md).
- **Paths**: `/etc/noust`, `/var/lib/noust` (the store is now `noust.db`),
  `/var/backups/noust`, `/etc/nginx/noust-upstreams` and `~/.local/share/noust`. Noust's own
  logs go to `/var/log/noust`; `/var/log/wasm` is left as it was.
- **`noust migrate-from-wasm`** moves a WASM server onto the new names: each directory with
  one atomic rename on the same filesystem and a symbolic link at the old name, the store
  renamed after a checkpoint and never recreated, WASM's default paths in `config.yaml`
  updated, blue/green includes and PHP-FPM pools renamed behind `nginx -t` without dropping a
  request, and Noust's own units replaced one at a time, each put back if its replacement
  does not come up. It runs from the packages' upgrade and on the first command run as root
  (not inside a systemd unit, under `--dry-run`, or with `NOUST_NO_AUTO_MIGRATE=1`), and can
  be interrupted and run again. `--dry-run` shows the plan, `--json` reports for scripts.
- **Noust's own units** are `noust-web`, `noust-monitor`, `noust-cron-*`, `noust-backup-*` and
  `noust-previews`, marked "Generated by Noust"; units marked "Generated by WASM" are still
  recognised.
- **Application units do not change**: `<app_name>.service`, including the `wasm-` prefix of
  units deployed before WASM 0.14.1. Nor do application directories, sites, domains,
  certificates, backups, the API, tokens, sessions or two-factor enrolment.
- **Environment variables**: `NOUST_*` first, `WASM_*` still read.
- **API**: new API tokens start with `noust_tok_` and a new master token with `noust_`; tokens
  issued by WASM keep working. `/health` reports `noust-web`. `GET /api/services` takes
  `noust_only` (`wasm_only` still read). The session reports `renamed_from_wasm`. Cookies,
  the CSRF header and the WebSocket subprotocols keep their `wasm` names.
- **Repositories** may name their nginx overrides `noust.nginx.yaml`; `wasm.nginx.yaml` is
  still read.
- **The console** is called Noust: a new logo, favicon, titles and texts, in English and
  Spanish, and a notice, once per browser, on a server that ran WASM.
- **The Python package** is `noust`; the repository is `github.com/Perkybeet/noust`.
