# Noust 4.4 changelog

Changes since Noust 4.3.0. What to do before updating is in [UPGRADING-4.4.md](UPGRADING-4.4.md).

## Before you upgrade

[UPGRADING-4.4.md](UPGRADING-4.4.md) has the order of an update and the way back; this is what to know first.

- **The update takes the image pull of before 3.2.1 out of the unit of a Compose stack that still has it.** One
  exact line, with or without `-p`, in a unit that carries `# Generated by Noust`; nothing restarts, and the
  step says so and writes `compose.pull_removed` in the audit trail
  ([UPGRADING-4.4.md](UPGRADING-4.4.md#the-image-pull-of-before-321-leaves-the-unit)).

## The start of a Compose stack

What was left over from the check that holds a stack's start to what was judged (4.3.0, the first item of
[Security](CHANGELOG-4.3.md#security)).

- **A stack whose compose file does not resolve is taken from its containers.** When Docker Compose cannot
  resolve a stack's file (or it is not there) and Docker answers with containers of the stack, the step that
  brings stacks under the check writes the record from what the containers were given, takes the project from
  their labels and puts the check in the unit. A stack with no container, or with Docker not answering, stays
  as it was, and `noust health` says so with how many days it has waited; from the seventh day it is also in
  what needs attention
  ([UPGRADING-4.4.md](UPGRADING-4.4.md#compose-stacks-noust-could-not-take-over)).
- **A stack with no record has its containers and nothing else.** An update, a redeploy and an edit in the Docker
  zone no longer read what a stack "already had" from the compose file at the commit that served or from the file
  on disk, which whatever mounts the tree can write. The helpers that only read that history (the links an update
  changed and what it left unchanged) are gone.
- **`noust health` says when a unit is not the one Noust wrote.** A unit that carries `# Generated by Noust` and
  starts something else (somebody edited it and left the line) is named, with how to mend it; an addition of the
  unit that replaces or adds to `ExecStart=` is named with its path, as the ones that empty `ExecStartPre=` were.
  Noust touches neither.
- **What is to be looked at about how the stacks start has a line of its own in `noust health`**, `Compose
  stacks`, and no longer shares the build sandbox's. The shape of `GET /api/system/health` and of `noust health
  --json` is the same.
