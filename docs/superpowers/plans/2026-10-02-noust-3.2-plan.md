# Noust 3.2 - Plan de ejecución

> **Para agentes:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (cada flujo lo
> implementa un agente con TDD: test que falla, implementación mínima, test que pasa; lo revisa otro).
> Este plan fija qué hace cada flujo, qué ficheros son suyos, las interfaces que comparte y cómo se
> acepta. El diseño está en el spec; donde el plan y el spec discrepan, manda el spec.

**Objetivo:** publicar Noust 3.2.0: Docker Compose de verdad (ganchos, rollback consciente del
esquema, relevo sin cortes, adopción, sitio del operador, alias, copias de la base del stack,
despliegue por etiqueta), el servidor web a la vista (analizador sin pérdidas, edición visual,
diagrama animado), los compromisos de 3.1 y los ítems del dueño (53, 54, ...).

**Arquitectura:** oleadas de agentes en paralelo sobre la rama `dev/3.2`, con propiedad exclusiva de
ficheros; cada oleada termina con verificación y un commit mío. Módulos nuevos con interfaces fijas
(tabla de abajo) para que los flujos no se esperen; los ficheros grandes compartidos tienen un dueño
por oleada y los demás aportan módulos que ese dueño conecta.

**Stack:** Python 3.10-3.14 (FastAPI, Click, SQLite), React 19 + TypeScript + Vite + Tailwind v4 +
Base UI 1.8, Playwright, arnés Docker con systemd (y Docker dentro, desde esta versión).

**Spec:** `docs/superpowers/specs/2026-10-02-noust-3.2-design.md`.

## Restricciones globales

- Las cuatro reglas de `CLAUDE.md`: procesos solo por `CommandRunner` (argv, timeout, secretos por
  `env=`/`input=`); `except Exception` solo en una frontera de error y registrando; una implementación
  de cada cosa (la web es cliente de los managers); guardas en el punto de paso.
- Ninguna dependencia de runtime nueva (ni Python ni de la consola). Todo modelo de la API por
  `web/pydantic_compat.py` (pydantic 1.10 y 2).
- `noust.yaml` es entrada no confiable: esquema cerrado, rutas dentro de la app, sin `..`.
- Nombres `wasm` que se conservan: intactos. Los upstreams nuevos usan el prefijo `wasm_bg_`
  existente (`wasm_bg_<app>_<servicio>`); los ficheros de servidores van en
  `/etc/nginx/noust-upstreams/<app>/<servicio>.servers` (vía `core/paths.py`).
- Copy de la consola en inglés y español, frases completas en `panel/src/i18n`; la salida del sistema
  nunca se traduce ni se parafrasea.
- CSP estricta: nada de `style=` fuera del kit, `<style>` inyectado, `innerHTML`, SMIL ni librerías
  que los usen. Animaciones solo CSS declaradas en `app.css` (las para la regla de movimiento
  reducido).
- `docs/DESIGN.md` es normativo: el kit (`components/`) y su galería crecen antes que las páginas.
- Docstrings estilo Google; tipos modernos; errores accionables; comentarios que explican el porqué;
  sin emojis; commits sin referencias a asistentes.

## Reglas de trabajo para los agentes (se copian en cada encargo)

1. Solo tocas los ficheros de tu flujo. Los ficheros "compartidos por regiones" (tabla de interfaces)
   se editan solo con `Edit` mínimo en tu región, nunca con `Write`. Lo que toques fuera, en tu informe.
2. Nada de git que cambie estado (`commit`, `stash`, `checkout`, `reset`, `restore`, `clean`). Nada de
   sub-agentes ni forks. Nada de `uv run` en la raíz.
3. No regeneres artefactos compartidos: `panel/openapi.json`, `schema.gen.ts`, man pages,
   completions, `src/noust/web/static`. Consola: nunca `npm run build`; para `routeTree.gen.ts`,
   `npx vite build --outDir /tmp/<flujo>-build --emptyOutDir`. Si necesitas tipos de la API nueva
   antes de que yo regenere, decláralos localmente en tu `api/queries/<área>.ts` y dilo.
4. Ejecuta solo tus tests (`.venv/bin/pytest <tus tests> -n auto -q`), `ruff check`/`ruff format`
   sobre tus ficheros y `mypy` (Python), o `npx vitest run <tus rutas>`, `npx eslint <tus ficheros>`,
   `npx tsc -b` (consola). Node 22 en `~/.local/node22/bin`. Nunca vitest/E2E a la vez que pytest
   completo. Nunca Docker contra contenedores o volúmenes `proggest*` del anfitrión.
5. Store: tu esquema ya está en `src/noust/core/schema_v13.py` (oleada 0); si necesitas otra columna,
   añádela en tu constante de ese fichero y en su test.
6. Rutas nuevas de la API: en `src/noust/web/permissions/routes_<área>.py` (un test falla si no).
   Eventos de auditoría: `noust.core.audit.record(...)` y su entrada en `core/audit/catalog.py`.
7. Informe final (≤ 400 palabras): qué hiciste, ficheros, tests, qué queda y qué tocaste fuera.

## Foco de revisión

Entradas que el spec implica y que ningún test de flujo cubre solo; cada una tiene su test en el
flujo dueño:

1. **Una app Compose existente sin `noust.yaml` que se actualiza en 3.2**: se comporta como en 3.1
   salvo la copia de su base, que ahora se hace; si su base no se puede copiar (credenciales en un
   fichero secreto, imagen no oficial), el error dice cómo apagarla y nada se ha tocado (B1 y C1:
   `test_update_without_project_file_matches_3_1`, `test_stack_dump_failure_stops_with_fix`).
2. **Configuraciones que el analizador no modela** (Lua, `map`, `if`, `split_clients`, includes con
   comodín, directivas de módulos de terceros): ida y vuelta exacta o `ParseError` con línea, nunca
   un fichero alterado; la vista Estructura las muestra en bruto (P1:
   `test_unknown_constructs_round_trip`; U1: `shows raw directives it does not model`).
3. **Relevo que muere a medias** (el proceso de Noust se mata entre el cambio de upstream y la
   vuelta): el siguiente despliegue o `noust doctor` encuentra el relevo y el fichero de servidores
   apuntándole y lo resuelve sin dejar el sitio sin nadie (C2: `test_leftover_relay_is_resolved_first`).
4. **Central 3.2 con nodos 3.1**: las vistas Estructura y Diagrama y el combobox de zona piden
   endpoints que el nodo no tiene; la consola dice "este servidor tiene una versión anterior" y deja
   el texto (U1 y U2: E2E con un nodo simulado sin las rutas; arnés de flota).
5. **Ganchos del operador como vía de escalada**: escribirlos es `root_equivalent` con elevación y
   cuatro ojos; un `noust.yaml` del repo no puede elegir usuario, `privileged` ni montar nada (H1:
   `test_operator_hooks_need_root_equivalent`, `test_repo_hooks_cannot_escalate`).
